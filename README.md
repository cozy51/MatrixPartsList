# Matrix Parts List

複数のPL（CSV）を、部品を縦軸・PL番号を横軸とするマトリックス部品表へ変換するReactアプリです。CSVの帳票部と明細ヘッダーを見出し名から判定し、品番がない明細は `+` として扱います。データはIndexedDBへ自動保存されます。

## ローカル起動

Node.js 20以降を用意し、次を実行します。

```bash
npm install
cp .env.example .env.local
npm run dev
```

本番ビルドは `npm run build`、テストは `npm test` です。

## 操作

1. 「CSV・Excelを追加」、中央の初回案内、または左サイドバーの常設ドロップ領域でCSV・Excelファイルを選びます。登録済みPLがある状態でもサイドバーへ繰り返しドラッグ＆ドロップできます。Excelは先頭シートをPLとして読み込みます。
2. ファイル名が `PL名称_Ver.csv`、`PL名称_Ver.xlsx` などの場合は末尾のVer.を自動取得します。**Ver.は2桁まで**とし、`HJ09301010_26090817.csv` のようにダウンロード日時が付いたファイル名では3桁以上を誤って取得しないよう空にします。取得できない場合や3桁以上を入力した場合は、赤枠と理由を表示して登録できないようにするため、プレビューの入力欄へVer.を入力してください。
3. 改廃が `D` の明細は削除済みとして読み込み対象から除外します。保存済みデータ・JSON復元・クラウド読込時にも、改廃 `D` の明細を自動削除します。
4. PL番号、名称、Ver.、部品数をプレビューして登録します。多数のPLを同時に読み込んだ場合はプレビュー内をスクロールでき、登録・キャンセルボタンは下端に固定されます。同じPL・Ver.が登録済み、または同じ読み込み内で重複している場合は警告を表示し、重複が解消されるまで登録できません。
5. 「補材を表示」のチェックを切り替えると、品番が `+` の補材を一括で表示・非表示にできます。
6. 風船列のチェックボックスで任意の複数行を選択し、「選択行のみ」で選択した部品だけに絞り込めます。ヘッダーのチェックボックスでは表示中の行を一括選択・解除できます。
7. マトリックスの各PL列では通常の使用数 `1` を `●` で表示し、同じ部品が同一PL内に複数ある場合は実数を赤字で強調します。
8. 「ダッシュボード」タブでは、機種からユニットへ展開するツリーで登録PL数を一覧できます。ダッシュボードを起動時のデフォルト画面として表示します。ユニット行をクリックするとPL・PL名称・備考欄を展開し、PLごとに備考を保存できます。備考を更新すると同期状態は「未同期」に戻るため、更新後にGoogle Drive同期を実行してください。「部品表へ」の部分だけが、その機種・ユニットを選択した部品表へのリンクです。機種ごとの「Excel DL」から、ユニット名・PL・PL名称・Ver.・備考の登録一覧をダウンロードできます。
9. 左のチェックでPL列を表示・非表示にします。PLには昇順に `1.`、`2.`の連番を付け、左側一覧と表ヘッダーで同じ番号を表示します。「全選択」と「全選択解除」で、現在のユニットに属するPLだけを一括変更できます。画面タイトルの右側にユニット名、キーワード検索、風船フィルターを並べています。風船が `C` の注記行は常に除外します。
10. 「PL類似度」タブでは、基準PLを選び、共通部品数を全部品の和集合で割った類似度（Jaccard係数）の高い順にPLを確認できます。各PLには左側一覧・マトリックスと共通の連番を表示します。類似度の行をクリックすると、共通部品・基準PLだけの部品・比較PLだけの部品を詳細表で確認できます。展開した比較結果は、その組み合わせごとに概要と3分類を含むExcelへ出力できます。
11. 「図面リンク」タブでは、社内システムの図面（PDF・DXF）へのリンクを図番ごとに登録します。社内システムの品番マスタでリンクをコピーし、「クリップボードから取得」を押すと、リンクの展開・図番・管理番号・種別を自動判定します。クリップボードを読み取れないブラウザーでは、取り込み欄への貼り付け（Ctrl+V）でも同じ判定を行います。
12. Excel出力、JSONバックアップ・復元を利用できます。削除・上書き・復元では確認画面を表示します。Excelを出力するボタン（「Excel出力」「Excel DL」）はExcelの緑で統一し、部品表ツールバーでは「図面リンク取得」を塗りつぶしにして最も目立つようにしています。
13. 「機種」と「ユニット名」プルダウンを切り替えると、選択中の機種・ユニットに属するPLだけを一覧とマトリックスへ表示します。
14. ヘッダー右上の歯車ボタンから設定画面を開き、Google Drive同期、JSONバックアップ・復元、機種別の登録PL件数を確認できます。

マトリックスのPL列はPL番号の自然順、部品行は風船番号の昇順で表示します。同じ風船番号の中は**品番の昇順**に並べ、品番を持たない**補材（`+`）は最後**に置きます。補材どうしは、PL番号順に明細を調べたときの初出順を維持します。風船が `C` などの注記行は除外します。

同じ風船番号の行は同じ背景色でまとめ、風船番号が変わる先頭行には控えめな破線の区切りを表示します。隣り合う風船グループは同系統の濃淡が異なる薄いブルーを交互に使い、色の系統が変わる不自然さを避けています。品番が `+` の補材も風船番号を同一判定に含めるため、別の風船に属する補材を誤って統合しません。

左側のPL一覧と右側のマトリックスはそれぞれ独立してスクロールします。マトリックスを縦スクロールしても列の項目名は上端に固定されます。

### 部品図の互換（10桁目の違い）

部品図（品番の9文字目が `5`・`6`）は、**10桁目が違っても互換**です（材質違いなど）。10桁目を除いた先頭9桁を「基本番号」とし、基本番号が同じ品番が表示中のPLに2つ以上あるときは、次のように示します。

| 表示 | 意味 |
| --- | --- |
| 品番の10桁目に下線 ＋ `互換` の印 | 10桁目だけが違う品番が他にもある |
| 品番セルの左に紫の線 | 同じ基本番号の行のまとまり |
| PL列の `○` | そのPLは、この行の品番ではなく**互換品**を使っている |

例: 風船102の `HJ06158060`（SUS304-B）と `HJ06158061`（SUS303-B）は、どちらの行にも `●` と `○` が並ぶため、**10桁目の違いを無視すれば両方のPLで共通**だと分かります。マウスを重ねると、互換の品番と、そのPLが使っている品番を確認できます。表の上には、互換の組数を添えた凡例を表示します。

`●` と `総計` は従来どおり**その品番そのもの**の使用数です（`○` は数に含めません）。組立図・PL・購入品は対象外です。

左側の部品情報列は `風船`、`品番`、`Ver.`、`品名`、`数量`、`材質・メーカー` の順です。`Z` で始まる品番は購入品のため、品番を濃い緑の太字で表示して見分けられるようにしています。横スクロール時も各固定列の間に空白が生じないよう、列幅を固定しています。

CSV・Excel読み込み時はファイル名とPL名称から機種・ユニットを推定します。判定できない場合、または現在選択中の機種・ユニットと異なる場合は、プレビューで内容を選択したうえで「機種またはユニットを確認しました」にチェックしてから登録します。

左側の登録済みPLとPL番号のヘッダーは、どちらもマウスを重ねるかキーボードでフォーカスすると、PL名称をダーク背景のツールチップで確認できます。PL番号のヘッダーは部品情報列と異なる色で表示します。PL番号へマウスを重ねるかキーボードでフォーカスすると、PL名称をダーク背景のツールチップで確認できます。PL番号とVer.は `XXX10 v11` の形式で隣り合わせに表示します。1桁のVer.は `v05` のように0埋めして2桁へ統一します。PL列と左側のPL一覧はいずれもPL番号の昇順で表示し、`HH1`・`HJ0` で始まる標準PLには読みやすい略称 `STD` を表示します。

UTF-8 CSVに対応します。不正な文字コード、空ファイル、必須見出し（風船・品番・品名）がないファイルはエラー表示され、既存データは維持されます。

## 図面リンク

「図面リンク」タブは、社内システム上の図面と3Dモデルを部品表から直接開くための機能です。図番と品番は基本的に同じですが、複数図面や流用図面では一致しないため、部品表（PL）とは**別のデータ**として管理します。

- 1件の図面リンクは、図番・**図面区分（組立図 / 部品図）**・種別（PDF / DXF / 3Dモデルの EASM など）・管理番号・リンク・対象品番・備考で構成します。
- 種別は拡張子から判定します。`.pdf` `.dxf` `.dwg` `.tif` は図面、eDrawings の `.easm` `.eprt` `.edrw` や `.sldasm` `.sldprt` `.step` `.igs` は3Dモデルとして扱います。同じ図番でも種別ごとに別レコードとして残るため、図面と3Dモデルを並べて登録できます。
- 図面区分は番号の9文字目のコードから自動判定します（`1`・`4` が組立図、`5`・`6` が部品図）。判定できない番号や例外は、登録画面の「区分」から手で設定できます。
- 対象品番は複数登録できます。1つの図面を複数品番へ流用する場合は品番を追加し、逆に1つの品番が複数図面を持つ場合は図面を複数登録します。図番と異なる品番はオレンジ色のチップで区別します。
- 同じ図番かつ同じ種別を再取得した場合は1件へまとめ、対象品番だけを統合します。PDFとDXFは別レコードとして残します。

### 11桁の図番と品番の対応

図番が11桁になる場合が2通りあり、いずれも10桁の品番へ読み替えて部品表とリンクします。

| | 品番 | 図番 | 内訳 |
| --- | --- | --- | --- |
| 機械図面の組図 | `HH110A0040` | `HH110A00410` | 品番の10桁目は `0` に据え置き、図番の10桁目がVer `1`、11桁目が枚数 `0`（1枚目） |
| 機械図面の組図（Verが英字） | `HH12302010` | `HH1230201C0` | Verは `9` の次が `A` へ繰り上がるため、図番の10桁目は数字とは限らない |
| 電気図面 | `HH01008043` | `HH010080430` | 外注のため品番そのものの10桁目を改訂で上げ（`…41`、`…43`）、図番はその品番に枚数 `0` を足した形 |

図番の10桁目（Ver）は `0`〜`9` の次が `A`・`B`・`C` と英字へ繰り上がります。11桁目（枚数）は必ず数字です。

図番の末尾にもう1桁付く場合、その12桁目は用紙サイズ（`4` = A4）です。図面そのものを指す番号ではないため、図番は11桁までとして扱い、画面にも出しません（`HD1AG0064204` → 図番 `HD1AG006420`、品番 `HD1AG00642`）。元のファイル名は図番の下にそのまま表示します。

図番だけではどちらの数え方か決まらないため、`先頭10桁` と `先頭9桁 + 0` の両方を品番の候補とし、**部品表に実在する品番（明細の品番とPL番号）を優先**して選びます。どちらの候補も部品表になければ、**同じ基本番号（先頭9桁）の品番**へ結び付けます。図面や3Dモデルが新品番で登録され、部品表には旧品番が載っている場合（3Dモデル `RJ0MT017440` と部品表の `RJ0MT01742` など）に対応するためです。候補そのものが部品表にあるときは広げないので、別Verの品番へ誤って付くことはありません。取り込み時は選んだ品番を対象品番へ加え、すでに図番だけで登録済みの図面も、部品表からは候補の品番でたどれます。編集画面の「図番から品番」ボタンでも同じ品番を追加できます。10桁の図番（図番＝品番）は読み替えません。

### CAD ID（図面の流用）

材質違いなど見た目が変わらない場合、社内システムでは品番に **CAD ID** を登録して図面を共用します。このアプリでも、PLの図面をCAD IDの品番から流用できます。図面リンクとは件数の桁が違うため、**「CAD ID」タブ**として独立させ、スクロールせずに登録・確認できるようにしています。

- 「CAD ID」タブで、`PL番号 → CAD ID` を登録します。入力欄は入力内容に応じて枠の色が変わり、登録できる状態のときだけ「✓ CAD IDを登録」ボタンを押せます。押せない理由（PL以外の番号、PL番号とCAD IDが同じ、未入力）は入力欄の下に表示します。例: PL `HH11002010`（浸炭仕様）に CAD ID `HH11001010` を登録すると、`HH11001010` の図面をそのまま開けます。
- 登録できるのは **PL（10桁目が `1`）の番号だけ**です。それ以外を入れるとエラーになります。
- 1つのPLにつきCAD IDは1件です。登録し直すと上書きします。
- 一覧はPL番号・CAD IDで検索でき、CAD ID側に図面があるかもその場で確認できます。
- 流用した図面のバッジは**破線と `CAD` の印**を付け、通常の図面と区別します。マウスを重ねると「CAD ID HH11001010 から流用」と表示します。PL番号のツールチップにもCAD IDを表示します。
- CAD IDの対応表は図面リンクと同じファイル（`MatrixPartsList-drawings.json`）へ保存し、同じタイミングでGoogle Driveへ同期します。

### 取り込み手順

1. 社内システムの品番マスタで、図面欄の `PDF` `DXF` や、3Dモデル欄の `EASM` のリンクをコピーします（右クリック →「リンクのアドレスをコピー」）。
2. 「図面リンク」タブの「クリップボードから取得」を押すか、この画面で貼り付け（Ctrl+V）します。入力欄の外であれば、画面のどこで貼り付けても取り込みます。**マトリックス部品表のツールバーにも「図面リンク取得」ボタンがあり、タブを切り替えずに取り込めます**（登録結果はその場に表示し、図番を判定できないリンクがあるときだけ「図面リンク」タブへ切り替えます）。
3. リンクから図番・管理番号・連番・種別・図面区分を自動判定します。`.../pdf/HH1/4397264_HH110A5060.pdf` のように `管理番号_図番.拡張子`、`.../eDrawings/HH1/4658515_HH121005400_2.easm` のように `管理番号_図番_連番.拡張子` の形式を想定し、`file.proxy?url=...` のプロキシリンクは実ファイルのURLまで展開して判定します。開くときは認証を通すため、コピーしたリンク（プロキシURL）をそのまま使います。
4. 図番・リンク・対象品番がそろっていれば、**登録ボタンを押さずにそのまま登録**します。図番を判定できなかったものだけ、確認用の入力欄へ出します。

多数の図面をまとめて登録できるよう、次の動きにしています。

- 複数のリンクを1行ずつまとめて貼り付けると、全件を続けて登録します。
- 取り込みが終わると貼り付け欄は空になり、そのまま次のリンクを貼り付けられます。
- 同じ図番・同じ種別・同じ連番を取り込み直した場合は新規ではなく更新として扱い、備考や手で足した対象品番は残します。連番が違えば別の図面として登録します（`..._1.easm` と `..._2.easm` は2件になります）。
- 直前の取り込み結果は「今回の取り込み」に一覧表示し、登録・更新の別を確認して、その場で編集できます。
- 「クリップボードから取得」と部品表の「図面リンク取得」は、押した時点で登録する操作のため、**設定に関わらずそのまま登録**します。
- 貼り付け（Ctrl+V）の分だけ1件ずつ内容を確かめたい場合は、「貼り付けたときも自動で登録する」のチェックを外します（設定はブラウザーに保存されます）。

登録した図面・3Dモデルは、マトリックス部品表の品番セル、**PL列のヘッダー**、左の**登録済みPL一覧**に `PDF` / `DXF` / `EASM` のバッジとして表示され、クリックすると別タブで開きます。PL列のヘッダーと左一覧には、そのPL番号に対応する組図（PL番号の11桁図番）を表示します。PL列の幅を広げないよう、`STD` とバッジはPL番号の下の行へ折り返し、バッジが増えたときはその行の中で折り返します。

バッジは色で見分けられます。図面は区分に合わせて組立図が緑、部品図がオレンジ、区分が未判定のものはインディゴ、3Dモデルは紫です。並び順は 図面（PDF → DXF）→ 3Dモデル で、1か所につき先頭の3種別までを表示します。マウスを重ねると、区分または3Dモデルの別と図番を確認できます。図面リンク一覧は検索とExcel出力に対応します。

### 図面が複数枚あるとき

何枚目かは次の2通りで決まります。

| ファイル名 | 図番 | 何枚目か |
| --- | --- | --- |
| `4397260_HH110040100.pdf` | `HH110040100` | 図番の11桁目 `0` → **1枚目** |
| `4397262_HH110040102.pdf` | `HH110040102` | 図番の11桁目 `2` → **3枚目** |
| `4658515_HH121005400_1.easm` | `HH121005400` | ファイル名末尾の連番 `1` → **1枚目** |
| `4658515_HH121005400_2.easm` | `HH121005400` | ファイル名末尾の連番 `2` → **2枚目** |

図番が同じでも連番が違えば別の図面として登録します（eDrawingsのように、同じ図番で複数ファイルが用意される場合に対応します）。図面リンク一覧でも、連番のあるものには `2枚目` を表示します。

同じ種別の図面が複数枚あってもバッジは**種別ごとに1つ**にまとめ、`PDF 3 ▾` のように枚数を添えます。押すとポップアップが開き、「1枚目」「2枚目」…と図番・ファイル名を見ながら開く図面を選べます。バッジの数はPL列の幅に影響しません。1枚しかない種別は、これまでどおり押すとすぐ開くリンクのままです。

## アイコン・Favicon

アプリのアイコンは、マトリックス部品表そのものを図案化しています。左の3本のバーが部品行、右の2列のドットがPL列で、使用部品を `●` として示します。1列目は選択中のPLとして白いピルで強調しています。配色はUIと同じインディゴ〜バイオレットのグラデーションです。

生成物は `public/` にあります。

| ファイル | 用途 |
| --- | --- |
| `icon.svg` | アイコン原本（ヘッダーのロゴ `src/BrandMark.tsx` と同じ図柄） |
| `favicon.svg` / `favicon.ico` | ブラウザーのタブ。16px前後でも潰れないよう行を2本に減らした簡略版 |
| `apple-touch-icon.png` | iOSのホーム画面（180px・透過なし） |
| `icon-192.png` / `icon-512.png` | PWA・`site.webmanifest` |
| `icon-maskable-*.png` | Androidなどの切り抜き（安全領域へ縮小済み） |

デザインを変更したときは、次のコマンドで全サイズを再生成します。

```bash
pip install cairosvg pillow
python3 scripts/generate-icons.py
```

## Google Cloud / Drive設定

1. Google Cloud Consoleでプロジェクトを作成し、**Google Drive API**を有効にします。
2. OAuth同意画面を設定します。テスト中は利用者をテストユーザーへ追加します。
3. 「APIとサービス > 認証情報」で **ウェブ アプリケーション** のOAuth 2.0クライアントIDを作ります。
4. 承認済みJavaScript生成元へ開発用の `http://localhost:5173` と本番URLを登録します。
5. `.env.local` に `VITE_GOOGLE_CLIENT_ID=...apps.googleusercontent.com` を設定し、開発サーバーを再起動します。

クライアントシークレットは不要であり、フロントエンドへ設定しないでください。ログイン後は `drive.file` スコープを使い、`WebAppsData` フォルダー（Folder ID: `1SWmOnYn98EN5nZs7Jsi3vBLkuJa4B_O6`）配下の `MatrixPartsList/MatrixPartsList-latest.json` に保存します。図面リンクとCAD IDの対応表は、同じ `MatrixPartsList` フォルダー内の別ファイル `MatrixPartsList-drawings.json` へ保存し、部品表とは独立した `revision` で同期します。図面リンクはログイン時に新しい方（クラウド／ローカル）を自動採用します。保存先の `WebAppsData` は名前ではなくこのFolder IDで直接指定します。名前で見つかる旧 `WebAppsData` や、さらに古い `WebAppData` にだけデータがある場合は一度読み込み、次回の書き込みでFolder ID指定の `WebAppsData` へ移行します。同期前にクラウドの `revision` を確認し、クラウドが新しければ選択画面を出します。通信エラーでもローカルデータと操作は維持されます。Googleのアクセストークンはメモリー内だけに保持します。

> `drive.file` はこのアプリが作成したファイルだけにアクセスする安全性を優先したスコープです。別環境で既に作られた同名ファイルを自動検出する必要がある運用では、Googleの審査要件を確認したうえでスコープ設計を見直してください。
